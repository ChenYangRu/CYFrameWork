# Config/ · 运营配置表

## 放什么

| 内容 | 格式 | 说明 |
|---|---|---|
| 数值表 | `.json` / `.bytes` | 战斗、成长、掉落、商店价目 |
| 活动表 | `.json` | 开服活动、限时商店、签到 |
| 本地化索引 | `.json` | 语言码 → 文案表路径 |

## 不许放

- 客户端硬编码常量（该进配置的必须进配置，否则改一次要发版）
- 密钥、Token、内网地址、管理后台 URL
- 与 `Resources/Config/` 重复的内容 —— 那边是**框架启动配置**（launch/resource/network），
  这里是**游戏内容配置**，两者职责不同，不要混放

## 限制

| 项 | 规范 |
|---|---|
| 单表大小 | ≤ 512 KB（超过就拆表或改二进制） |
| 编码 | UTF-8 无 BOM |
| 结构 | 顶层必须是数组或对象，字段名小写下划线 |
| 版本 | 每张表带 `ver` 字段，客户端与服务器比对 |
| 校验 | 打包前必须跑 Schema 校验（字段缺失/类型错在运行时会静默变默认值） |

## 为什么放 BundleAssets 而不是 Resources

`Resources/` 下的内容**无法热更**（编进包体）。运营配置必须能热更，所以放这里走 YooAsset。

## 打包注意

- 打 `builtin` tag：进游戏前必须已有基础配置，否则首屏就是空白。
- 配置表**不要和 UI 打同一个 bundle**：配置更新频率远高于 UI，绑一起会导致每次改数值都重下 UI 包。
- 二进制表（`.bytes`）比 json 小 30~50%，但可读性差；**只在超过 300KB 的表上**用二进制。
