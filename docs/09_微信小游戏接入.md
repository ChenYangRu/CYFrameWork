# 微信小游戏接入（WX-WASM-SDK）

> 2026-11-04 · 对应菜单：`框架 → 微信小游戏`
> 目标：Unity 2021.3 + WebGL → 微信小游戏（先跑通，再谈分包与商业化）

## 一、为什么用官方 V2 而不是自己写转换

Unity WebGL 产物是 `index.html + .wasm + .data`，微信小游戏要的是「一个小游戏工程 + 首包 ≤ 4MB（总包 20MB，可分包）」。
官方 SDK 提供的不只是转换脚本，还有：

- 运行时适配层（`WX.InitSDK`、生命周期、触摸、音频、本地存储）；
- 转换器（把 WebGL 产物改写成小游戏可加载结构）；
- 分包工具（主包只留首屏）。

自己拼这套东西的代价远大于接一个官方 SDK。

## 二、一次性准备（只做一次）

菜单 **`框架 → 微信小游戏`**，全部在编辑器内完成，不依赖浏览器：

1. **`下载并导入 WX-WASM-SDK`**
   编辑器内用 `UnityWebRequest` 直接拉官方直链（约 40MB，2026-11 核对版本 0.1.35），下完自动导入。
   包落在**工程上级目录** `WX-WASM-SDK-V2.unitypackage`（不进 Assets）。
   已下过会问「直接导入 / 重新下载」。
2. **`一键接入 WX-WASM-SDK`**
   检测是否已装 + 把下表设置一次配到位。没装时会给你三条路：下载并导入 / 只做设置 / 选择本地包。
3. 导入完**再点一次「一键接入」**，让设置落到新导入的 SDK 上。

### 菜单自动改的设置（漏一项就会真机白屏或超包）

| 设置 | 值 | 漏了会怎样 |
|---|---|---|
| Scripting Backend（WebGL） | IL2CPP | 小游戏不支持 Mono |
| Api Compatibility | .NET Standard 2.0 | SDK / TMP 编译不过 |
| Compression Format | **Disabled** | 平台再压一层 → 加载失败，编辑器无提示 |
| Linker Target | Wasm | 产物结构不对 |
| Threads Support | 关 | 小游戏无线程模型 |
| Managed Stripping | Low | SDK 走反射，Strip High 会裁掉 → 空引用 |
| Strip Engine Code | 关 | 同上 |
| Define | `WX_MINIGAME` | 业务侧分平台逻辑没开关 |

> 颜色空间（Color Space）没动：改它会让全工程贴图重导入，很慢，按项目实际情况再定。

### 官方入口（链接会复制到剪贴板）

- SDK 安装指引：https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/SDKInstaller

## 三、每次出包

1. `框架 → 微信小游戏 → 构建微信小游戏`
   - 装了 SDK 会反射调用 `WeChatWASM.WXConvertCore.DoExport()`；
   - 找不到入口会明确报错，不会静默出半成品。
2. 用微信开发者工具打开转换产物目录，填 AppID。
3. **真机预览**（开发者工具的性能与音频行为和真机差很远，音频尤其）。

## 四、已知坑

1. **首包超 4MB**：主包只放入口场景 + 字体 + 图标，其余走 CDN（资源侧见 `03_打包与资源更新.md`）。
2. **字体**：TMP 必须静态子集，整包 8MB 的 NotoSansSC 放不进去。
3. **存档**：小游戏文件系统受限，用 `PlayerPrefs` 或框架的 txt 存档（`Framework/Data`），**不要自己拼 File IO**。
4. **音频**：首次进入需用户交互后才能播，BGM 要在第一次点击后启动。
5. **平台宏**：业务分支只判 `WX_MINIGAME`，别在业务里散落 `UNITY_WEBGL`。
6. **YooAsset 微信文件系统**（如项目接了资源热更）：需要 `WEIXINMINIGAME` / `UNITY_WECHATMINIGAME` 宏之一生效，
   否则 `WechatFileSystemCreater` 类型不存在（它整段包在 `#if UNITY_WEBGL && (...)` 里）。
