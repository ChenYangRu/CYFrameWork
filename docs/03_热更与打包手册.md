# 03 · 热更与打包手册

> 目标读者：要出包 / 要发热更的人。全过程只需 5 个菜单 + 1 个面板。

---

## 零、一次性准备（每个工程只做一次）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 菜单 `框架/资源/初始化 YooAsset 收集器（首次必点）` | 生成 `BundleCollectorSetting`，建好 `HotUpdate` / `UI` 两个分组 |
| 2 | 菜单 `框架/热更/0. 登记热更程序集到 HybridCLR` | 把 `launch.json` 的名单写进 `ProjectSettings/HybridCLRSettings.asset` |
| 3 | 菜单 `HybridCLR/Installer` → **Install** | 拉取 il2cpp_plus 并改造本地 IL2CPP。**必须手动点，显示 √ 不等于装完**。首次几分钟 |
| 4 | Player Settings | `Scripting Backend = IL2CPP`、`Target Architectures = ARM64`、`Api Compatibility Level = .NET Framework` |
| 5 | 菜单 `框架/热更/9. 自检：配置一致性` | 全绿再往下走 |

> HybridCLR 安装包已内嵌在 `Packages/com.code-philosophy.hybridclr`（8.15.0，离线可用），不需要联网拉包。

## 一、开发期：编辑器直连（不出包、不编译 DLL）

`Game.HotUpdate` 是正常 asmdef，Unity 会把它编译到 `Library/ScriptAssemblies/Game.HotUpdate.dll`。
启动器在编辑器分支直接取 `AppDomain` 里已加载的那个程序集：

```csharp
#if UNITY_EDITOR
    var editorAsm = FindLoaded(asmName);   // 直接反射调用，改代码 Ctrl+S 生效
#endif
```

所以**日常开发体验和普通工程完全一样**，热更只在上线前才需要走打包流程。

## 二、发版：出热更 DLL（3 个菜单）

```
框架/热更/3. 一键 GenerateAll（DLL + link.xml + 补元）   ← 首次/大改后跑
   等价于：
   ① CompileDll          → HybridCLRData/HotUpdateDlls/{platform}/Game.HotUpdate.dll
   ② GenerateLinkXml     → HybridCLRGenerate/link.xml（防裁剪）
   ③ StripAOTDlls        → HybridCLRData/AssembliesPostIl2CppStrip/{platform}/*.dll
```
随后工具自动做两件搬运（也可单独点 1 / 2）：

| 菜单 | 产物 | 去向 | 是否随包 |
|---|---|---|---|
| `1. 编译热更 DLL → .bytes` | `Game.HotUpdate.dll.bytes` | `Assets/BundleAssets/HotUpdate/` | ❌ 走 CDN 热更 |
| `2. 生成 AOT 补元数据 → Resources` | `mscorlib.bytes` 等 | `Assets/Resources/AOTMetadata/` | ✅ 必须随包 |

**为什么补元数据必须随包**：它要和主包已编进包体的 IL2CPP 代码**完全同源**，热更一个字节都不行。

**为什么要改成 `.bytes`**：Unity 不认 `.dll` 作为可加载资源；`.bytes` 会被导入为 `TextAsset`，才能进 AB、才能 `Assembly.Load(bytes)`。

## 二·补 · 四种运行模式与更新流程

### 2.1 四种模式（对应 YooAsset 的四种初始化方式）

| 模式 | 枚举值 | 资源从哪来 | 有更新流程 | 用在哪 |
|---|---|---|---|---|
| `EditorSimulate` | 0 | 直接读 AssetDatabase（模拟构建） | ❌ | 日常开发，改图即见 |
| `Offline` | 1 | 随包的 StreamingAssets | ❌ | 单机包 / 无网环境验收 |
| `Host` | 2 | 内置兜底 + 远端增量下载到本地沙盒 | ✅ | **Android / iOS / PC 正式包** |
| `Web` | 3 | 全部走 HTTP 直读（不落磁盘） | ✅ | WebGL / 微信小游戏 |

**`Host` 与 `Web` 的本质区别**：Host 把 bundle 下载到 `persistentDataPath` 再读，可离线复玩；Web 端没有可写文件系统（小游戏的虚拟 FS 语义还不稳定），所以只能"边下边读 + 依赖浏览器缓存"。

### 2.2 开发期怎么切（不用改 json）

菜单 `框架/资源/运行模式/` 四选一，勾选状态实时显示：

```
框架/资源/运行模式/编辑器模拟（EditorSimulate）
框架/资源/运行模式/离线单机（Offline）
框架/资源/运行模式/联机热更（Host）
框架/资源/运行模式/Web / 小游戏（Web）
框架/资源/运行模式/清除覆盖（跟随 resource.json）
框架/资源/打印当前资源模式        ← 同时显示 json 值 / 覆盖值 / 实际生效值
```

实现：覆盖值存 `EditorPrefs`，`ResourceConfig.Load()` 里覆盖 json 的 `playMode`，**只在 `UNITY_EDITOR` 编译单元里存在**，真机永远以 `resource.json` 为准。这样不会出现"误把 Host 配置提交上去"的事故。

### 2.2.1 也可以在 Inspector 里选（进包生效）

`Bootstrap` 组件上有一组序列化启动参数，**随场景进包，真机同样生效**：

| 字段 | 作用 |
|---|---|
| `autoStart` | 是否自动启动（关掉可写自动化脚本手动 `GameLauncher.Create().Run()`） |
| `resourcePlayMode` | `UseConfig` / `EditorSimulate` / `Offline` / `Host` / `Web` |
| `skipResourceSystem` | 纯业务联调时跳过资源系统（资源加载全失败但不阻塞启动） |

场景里没有 Bootstrap 时，`AutoBoot` 会运行时兜底 new 一个，字段取默认值（`UseConfig`）——
所以**要选值就必须把组件挂到场景里**：

```
菜单 框架/启动/在当前场景添加 Bootstrap（可配启动参数）
→ 选中 [Bootstrap] → Inspector 里选 resourcePlayMode → Ctrl+S 保存场景
```

**优先级（高 → 低）**

```
Bootstrap(Inspector，随场景进包，真机生效)
  ↓
编辑器菜单「框架/资源/运行模式」（EditorPrefs，仅编辑器）
  ↓
Assets/Resources/Config/resource.json
```

这样排的理由：Inspector 值是"这个包明确要什么"，属于出包决策；菜单覆盖只是开发期临时手段，
不应该盖掉打包时定下的值。

### 2.3 更新流程（Host / Web 共用，7 段）

```
Initialize      初始化 YooAsset 包裹
  ↓
RequestVersion  拉远端 .version，比对本地版本
  ↓
LoadManifest    加载并校验清单
  ↓
Prefetch        比对差异，算出"要下几个文件 / 多少 MB"
  ↓
WaitConfirm     ★ 流量提示：把 FileCount / TotalBytes 交给 UI 问玩家
  ↓              （不注入确认回调则静默下载，仅适合编辑器/自动化）
Downloading     增量下载 bundle（含热更 DLL）+ 进度/速度
  ↓
Cleanup         清理不再使用的旧 bundle
  ↓
Done            进入热更 DLL 加载 → 反射调用业务入口
```

代码里反映为 `ResourceService.Stage` + `OnStageChanged(stage, message)` 事件，UI 直接订阅即可显示"正在检查版本 / 正在下载"。

### 2.4 下载确认（这条不能省）

```csharp
// 启动器里注入（GameLauncher 已接好，默认弹启动页的确认框）
Resource.ConfirmDownload = (info, answer) =>
{
    // info.FileCount / info.TotalBytes / info.RemoteVersion
    ShowDialog(info.ToPlayerText(), ok => answer(ok));
};
```

- **必须在加载热更 DLL 之前**问 —— 热更 DLL 也在这批下载里
- 回调必须被调用一次（`answer(true/false)`），否则启动会一直等
- 玩家拒绝 → 启动失败并提示"已取消更新"，不要静默继续

> 移动网络下静默吃掉几十 MB 是差评高发点，这条比任何加载优化都重要。

## 三、打包：YooAsset 构建 → CDN

```
1) 菜单 框架/资源/打开 YooAsset 打包器  → 选包裹 GamePackage → 选管线 ScriptableBuildPipeline
2) 资源版本号建议用时间戳（YooAsset 默认），构建 → 产物目录形如 Buildin/Android/v2026-11-04-xxxx
3) 菜单 框架/资源/同步构建产物 → CDN 目录  → 选上一步的产物目录
   工具会拷到：{工程根}/CDN/{平台}/{appVersion}/{资源版本}/
4) 把 CDN 目录整体上传到你的静态服务器，目录结构与本地一致
5) 改 Assets/Resources/Config/resource.json：
     playMode     = 2        （Host 联机模式）
     hostServer   = https://your-cdn.com/yourgame
     appVersion   = 1.0.0    （必须与 CDN 上的目录名一致）
6) 出 APK/AAB（IL2CPP + ARM64）
```

最终 URL 形态：

```
https://your-cdn.com/yourgame/Android/1.0.0/{资源版本}/.version
https://your-cdn.com/yourgame/Android/1.0.0/{资源版本}/{bundle}
```

> 目录约定与 `.version` 文件是热更判定的**唯一真相源**：客户端先拉 `.version` 比对，不同才拉清单与差异 bundle。

### CDN 配置硬要求

| 要求 | 原因 |
|---|---|
| `.version` 与清单文件 **禁止缓存**（`Cache-Control: no-cache`） | 缓存住就永远检测不到新版本 |
| 不要用带端口或双斜杠的 URL | YooAsset 拼 URL 时不做归一化，`https://a.com//Android` 会 404 |
| HTTPS 必须证书链完整 | Android 7+ 默认拒绝不完整证书链 |

## 四、验证热更闭环（必做两次）

### A. 资源热更（换图/改配置）

1. 改任意被收集的资源（例如 UI 图）
2. YooAsset 打包器重新构建 → 同步到 CDN → 上传
3. 手机打开游戏 → 启动页显示"下载资源 xx MB" → 进主界面，内容已更新

### B. 代码热更（改逻辑）

1. 改 `GameEntry.HotLogicVersion` 常量 `1 → 2`
2. `框架/热更/1. 编译热更 DLL → .bytes`
3. YooAsset 打包器重新构建（收集器会带上新的 `.dll.bytes`）→ 同步 CDN → 上传
4. 重开游戏 → 主界面「业务逻辑版本」显示 **v2** ⇒ 代码热更通了

> 只改数值（例如 `HotLogicVersion`）属于"重编译常量"，足以证明 DLL 被替换；逻辑改动同理。

### 判定失败在哪一环

| 现象 | 定位 |
|---|---|
| 启动页不显示"下载资源" | `.version` 没变 / CDN 被缓存 / `appVersion` 与目录不匹配 |
| 下载完仍显示旧版本 | 收集器没包含该资源 / 构建时没勾 Copy Buildin / 上传到了旧版本目录 |
| 报"类型不存在" | 缺补元数据（跑菜单 2）或该 AOT 类型被裁切（查 `link.xml`） |
| 报 `Assembly.Load` 失败 | `.dll.bytes` 不是当前 HybridCLR 版本编出来的 / 收集器漏了它 |
| 白屏无日志 | 补元数据在 DLL 之后加载（顺序被改过） |

## 五、Strip Level 与 link.xml

`Player Settings → Managed Stripping Level`：
- **Low/Medium**：一般够用，包体略大；
- **High**：包体最小，但会裁掉反射用到的类型（YooAsset / HybridCLR / JsonUtility 泛型都会中招）。

选 High 时**必须**保留 `HybridCLRGenerate/link.xml`（GenerateAll 自动生成并维护）并在 `Assets/link.xml`（如有）里补充业务反射类型。本工程已把 `link.xml` 由工具生成，不要手改生成物。

## 六、一次完整发版的顺序清单

```
□ 自检菜单全绿
□ GenerateAll（DLL + link.xml + 补元）
□ YooAsset 构建（ScriptableBuildPipeline）
□ 同步到 CDN/{平台}/{appVersion}/{资源版本}
□ 上传 CDN（先传 bundle，最后传 .version —— 避免用户拉到半套）
□ 出包（IL2CPP / ARM64 / 与 CDN 相同的 appVersion）
□ 真机验证：资源更新 + 代码热更 各一次
```

> **上传顺序很重要**：先传资源再传 `.version`，否则用户在传输中途打开游戏会拉到"清单说新版、文件还没上"的状态。
