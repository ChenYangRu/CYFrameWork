## 四、一页速查（贴在工位上那种）

**启动顺序（错一步就炸）**

```
资源更新（可选）→ 初始化数据服务 → 调业务入口
```

**四条禁令**

1. 业务代码不许写进 `Assets/Framework`（那是 AOT 层，改了要发版）。
2. 业务层不许直连 `YooAsset`，只走 `ResourceService`（将来换资源系统只改一个文件）。
3. 任何地方不许同步加载资源（小游戏不支持）。
4. 代码不做热更：`Game.Business` 随包发布，改代码 = 发新包（能热更的只有资源）。

**双模一句话**

| 模式 | 一句话 |
|---|---|
| Offline | 不创建网络服务，本地 txt 即权威，跳过登录直接进主界面 |
| Online | 创建 WebSocket，服务端为准，本地当缓存（断线可续玩） |

**三个"没资源也能跑"的兜底**

| 场景 | 兜底 |
|---|---|
| `BundleAssets` 里没资源 | 资源系统进**降级模式**，游戏照常进登录页 |
| 场景里没挂 `Bootstrap` | `AutoBoot` 运行时兜底创建 |
| 没有服务端 | 登录页「单机进入」 |

**四条判据（排障先用）**

| 现象 | 先查 |
|---|---|
| 真机「类型不存在」 | 是不是用了 `Type.GetType("字符串")` 且被 Strip 裁掉 |
| 热更不生效 | 版本号变没变 → CDN `.version` 的缓存头 |
| 加载报 location 找不到 | 资源的 location = 相对 `BundleAssets/` 的路径去扩展名 |
| 存档读回旧值 / 改了没落盘 | 实体是不是 public 字段；就地改后有没有 `MarkDirty()` |
| 编辑器工具刷屏/卡死 | `AssetDatabase.Refresh()` 后面有没有弹模态框 |

## 五、文档维护约定

- 新增/修改框架能力时，**同一提交**里更新对应文档；文档与代码不一致时以代码为准，但必须立刻修文档。
- `04_踩坑与判据.md` 只记录**真实发生过**的问题，每条必须能被"从现象判断到根因"复用，不写推测。
- 文档中不出现具体项目名、玩法数据、内网地址；示例一律用 `mygame` / `example.com` 这类中性占位。
