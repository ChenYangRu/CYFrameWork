# 01 · 架构设计

> 面向"要改框架 / 要评估能不能撑住项目"的读者。业务接入看 `02_接入指南.md`。

---

## 一、程序集分层（这就是"DDL 分步"）

| 程序集 | 目录 | 形式 | autoReferenced | 依赖 | 职责 |
|---|---|---|---|---|---|
| `GameFramework.Core` | Framework/Core | ❌ AOT | true | 无 | 事件总线、日志、状态机、主循环、定时器、对象池、路径 |
| `GameFramework.Network` | Framework/Network | ❌ AOT | true | Core | TCP / WebSocket 通道、拆包、心跳、重连、请求-响应配对 |
| `GameFramework.Data` | Framework/Data | ❌ AOT | true | Core | 离线存档：txt 序列化、增删查改、自动存档、原子写 |
| `GameFramework.Resource` | Framework/Resource | ❌ AOT | true | Core, YooAsset | 资源初始化/版本/清单/下载/加载 |
| `GameFramework.UI` | Framework/UI | ❌ AOT | true | Core, Resource, UnityEngine.UI | Canvas 分层、面板栈、遮罩、代码搭 UI |
| `GameFramework.Audio` | Framework/Audio | ❌ AOT | true | Core, Resource | 音频服务：BGM 交叉淡入、SFX 通道池、三层音量（不依赖 AudioMixer） |
| `GameFramework.Runtime` | Framework/Runtime | AOT | true | 上述六层 + YooAsset | 启动状态机、启动/更新界面、**离线/联网模式分叉** |
| `Game.AOT` | Game/AOT | ❌ AOT | true | 全部框架层 | `Bootstrap`：唯一 AOT 入口 |
| `Game.Business` | Game/Business | **随包编译** | true | 框架层（不含 AOT 入口） | 全部业务：界面、协议处理、玩法 |
| `GameFramework.Editor` | Editor | — | — | 全部 + YooAsset.Editor | 打包工具链菜单 |

### 为什么这么切

- **框架层与业务层分开**：框架层（`Assets/Framework`）稳定、极少改；业务层（`Assets/Game/Business`）天天改。分开后增量编译只编业务层，且能强制"业务不许反向污染框架"。
- **业务层保持独立程序集**：不并进 `Assembly-CSharp`，避免和框架层/第三方插件混编导致的编译域污染；也方便将来真要接热更时只需换加载方式。
- **`Game.AOT` 单独一个程序集**：它只有 `Bootstrap`/`AutoBoot`，是**组合根**——它引用框架层 + 业务层，把业务入口（`GameEntry.Start`）传给启动器；框架层因此完全不认识业务类型。

## 二、启动时序（顺序不可乱）

```
Bootstrap.Awake()                     [Game.AOT]
  └─ GameLoop.Ensure()                常驻主循环（DontDestroyOnLoad）
  └─ GameLauncher.Run()
       ├─ 0. GameLog 落盘 / 平台信息
       ├─ 1. 判定游戏模式（launch.json / Bootstrap / 菜单三层覆盖）
       │      Offline → 不创建 NetworkService；Online → 创建 WebSocket 通道
       ├─ 1.1 装配服务 → ServiceLocator
       │      DataService（最早起，业务 Start 里就可能读档）
       │      ResourceService / NetworkService（仅 Online）/ UIManager
       ├─ 2. 资源更新（YooAsset，EditorSimulate 模式直接跳过）
       │      初始化包裹 → 请求版本 → 加载清单 → 下载 → 清理   进度 5%~55%
       └─ 3. 调业务入口（委托，非反射）
              Bootstrap 把 GameEntry.Start 传给 GameLauncher.Run(entry)
              业务自行注册面板 / 协议 → 打开首个界面
```

失败即停在启动页错误面板，带「重试」按钮（`GameLauncher.Retry()` 会清服务重跑）。

**为什么顺序不能换**

| 若调换 | 后果 |
|---|---|
| 先开网络再启动数据 | 联网回调可能早于存档就绪，写存档时空引用 | `DataService` 必须在 `NetworkService` 之前初始化 |
| 业务入口在资源更新前调 | 业务可能马上要加载资源，包裹还没就绪 | 入口一定放在资源流程之后 |

### 2.1 双模分叉点（离线 / 联网）

```
GameLauncher.Flow()
  ├─ Mode = LaunchConfig.ResolveGameMode(cfg.gameMode)
  ├─ DataService.Init(Mode, slot)            ← 两种模式都有
  ├─ if (Mode == Online) NetworkService.Init(...)   ← 离线**不创建**
  └─ 反射进入 GameEntry.Start()
        ├─ Offline → 直接 EnterMain()（跳过登录）
        └─ Online  → UIManager.Open("Login") → WebSocket 握手 → 登录
```

## 三、各层设计要点

### 3.1 Core

| 组件 | 关键决策 |
|---|---|
| `GameLoop` | 唯一常驻 MonoBehaviour；承担主线程调度 + 协程宿主 + 全局 Tick。网络线程**禁止**直接碰 Unity API，一律 `Post` 回来 |
| `EventBus` | `Dictionary<Type, Delegate>`，零反射；`GetInvocationList` 分发，单个订阅者抛异常不影响其他 |
| `Fsm` | 状态内再切换走 `_pendingType` 延迟一帧，避免重入 |
| `TimerService` | 不用协程（协程数量一多 GC 抖动），挂在 `GameLoop.OnTick`；回调前先从链表摘除，允许回调里 Cancel 自己 |
| `ServiceLocator` | 业务只依赖抽象；**业务层只能取服务、不注册服务**（注册权在启动器，避免生命周期打架） |
| `GameLog` | 分级 + 文件落盘 + `OnLog` 钩子（接 Bugly/Sentry 只改一处） |

### 3.2 Network

线程模型（三层）：

```
收线程(Recv)          主线程(GameLoop)             业务
──────────           ─────────────────           ────────
socket.Receive
  → PacketSplitter
  → Post(Dispatch) ──▶ Dispatch(packet)
                         ├─ seq≠0 且有待处理请求 → 回调
                         └─ 否则 → 按 cmd 找 handler ──▶ handler(p)

发线程(Send) ◀── 队列 ◀── NetworkService.Send/Request（主线程）
```

关键点：

- **帧格式固定 12 字节头**：`[bodyLen u32][cmd u32][seq u32][body]`，大端。TCP 是流，只有长度前缀能无歧义切分半包/粘包。
- **`NoDelay = true`**：关 Nagle，小包即时发出，帧同步/实时指令必需。
- **心跳与超时分离**：`heartbeatInterval` 发 ping，`heartbeatTimeout` 判死；**任意包都算活跃**（不只 ping 回包），避免大流量时误判断线。
- **重连退避**：`base × 2^(n-1)`，封顶 30s，次数用尽则回调 `OnDisconnected(reason, false)`。
- **重连不重放请求**：业务语义各异，框架不猜；业务监听 `OnReconnected` 自行补状态。

### 3.3 Resource

`ResourceService` 把 YooAsset 3.0.5 收敛成一个协程：

| 模式 | 用途 | 初始化方式 |
|---|---|---|
| `EditorSimulate` | 日常开发 | `EditorSimulateBuildInvoker.Build()` 生成虚拟包（不打包 AB），无更新流程 |
| `Offline` | 单机 / 无网验收 | `BuiltinFileSystemParameters`，只读包内资源，无更新流程 |
| `Host` | Android / iOS / PC 正式包 | builtin 兜底 + sandbox 缓存，**有完整更新流程（7 段）** |
| `Web` | WebGL / 微信小游戏 | `WebServerFileSystemParameters`，全走 HTTP 不落磁盘，有更新流程 |
| `Offline` | 单机/包内资源 | `CreateDefaultBuiltinFileSystemParameters()` |
| `Host` | 正式发布 | builtin（兜底）+ cache（远端热更），`IRemoteServices` 主+备双地址 |

`Host` / `Web` 流程（7 段，全程可通过 `OnStageChanged` 观测）：
`Initialize` → `RequestVersion` → `LoadManifest` → `Prefetch` → **`WaitConfirm`（流量提示）** → `Downloading` → `Cleanup` → `Done`。

下载前会把 `ResourceUpdateInfo`（文件数 / 字节数 / 远端版本）交给 `ConfirmDownload` 回调，
由启动页弹框问玩家——**不注入该回调则静默下载**，只适合编辑器与自动化。

**业务禁止直连 YooAsset**：将来换 Addressables / 自研 AB 只改这一个文件。

### 3.4 UI

```
[UIRoot] (Canvas ScreenSpaceOverlay, sortingOrder=100, CanvasScaler 1920×1080)
 ├─ Layer_Scene   常驻 HUD
 ├─ Layer_Normal  主界面（同层互斥）
 ├─ Layer_Popup   弹窗（压栈，带遮罩）
 ├─ Layer_Top     顶层（设置/公告）
 └─ Layer_Tips    飘字（不阻挡）
```

- **注册式**：`UI.Register<LoginWindow>("Login", UILayer.Normal)`。面板由业务层自己注册，框架层不认识任何具体面板。
- **双构建路径**：给了 `prefabLocation` 走资源层 + 组件绑定；不给就调 `BuildUI()` 用 `UIUtil` 代码搭。**先跑通流程再接美术**，这是小团队最省时间的路径。
- **Esc / 安卓返回键** → `CloseTop()`（Normal/Scene 层不参与，避免把主界面关掉）。
- 面板刷新文本要自己节流（示例 `MainWindow` 用 0.5s），`Text` 脏标记代价不低。

### 3.5 Runtime（启动核心）

`GameLauncher` 只做三件事，不认识任何业务类型：

1. **判定模式**：`LaunchConfig.ResolveGameMode(...)` → 决定要不要创建 `NetworkService`。
2. **装配服务**：`DataService`（最先）/ `ResourceService` / `NetworkService`（仅联网）/ `UIManager` / `AudioService`，全部注册进 `ServiceLocator`。
3. **跑资源更新 → 调业务入口**：`Resource.InitializeAndUpdate(...)` 完成后执行 `Run(entry)` 传进来的委托；异常捕获后显示到启动页（带重试）。

> 入口用**委托**而不是"反射找某个类型"：代码不再热更，没必要为找入口引入字符串与反射；
> 也让 `GameFramework.Runtime` 与 `Game.Business` 之间没有任何引用关系。

## 四、代码发布策略（为什么没有代码热更）

| | 本框架的选择 |
|---|---|
| 代码 | **随包发布**（IL2CPP 全 AOT 编译），改代码 = 发新包 |
| 资源 | **可热更**（YooAsset 版本比对 + 增量下载） |

**为什么不带代码热更**

| 原因 | 说明 |
|---|---|
| 平台合规 | 微信小游戏等平台禁止运行时加载外部代码，`Assembly.Load` 属违规，审核过不了 |
| 成本 | 要带解释器 + 元数据补丁 + 双份程序集，首包与内存都更贵 |
| 风险 | 代码热更出错是"全员白屏"，且很难回滚（资源可以回滚到旧目录） |
| 收益 | 高频变更的是数值、活动、界面表现 —— 都在资源里 |

**那迭代效率怎么保证**

1. 数值 / 活动 / 文案 / 界面表现全部走资源与配置 → 不用发版。
2. 框架层与业务层分程序集 → 日常只编业务层，热重载快。
3. 编辑器用 `EditorSimulate` 资源模式 + 不做 DLL 流程 → 改完直接 Play，启动链路短。

> 如果将来确实需要代码热更（例如原生包），把业务程序集改回"加载式"即可：
> `GameLauncher.Run(entry)` 换成从 DLL 反射取入口，其余分层不用动。

## 五、扩展点（改框架时只动这些）

| 想加什么 | 动哪里 |
|---|---|
| 换传输协议（WebSocket/KCP） | 新增 `INetChannel` 实现，`NetworkService` 不改 |
| 换资源方案 | 只改 `ResourceService` |
| 加 UI 动效 / 异步打开动画 | `UIWindow.OnShow` 前后插 `Task`/协程，`UIManager.FinishOpen` 一处 |
| 加本地化 | `UIUtil.DefaultFont` + 文案表；文本统一走 key |
| 加 SDK（支付/统计/推送） | AOT 侧建 `GameFramework.Sdk` 程序集，热更层通过接口调用 |
| 多包裹（首包/下载包分离） | `ResourceService` 支持多 `ResourcePackage`，配置加数组 |
