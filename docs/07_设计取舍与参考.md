# 07 · 设计取舍与参考（对标开源框架）

> 对标仓库：`EllanJiang/GameFramework`（19 模块）
> 结论：**只借设计，不引依赖**。本文记录"为什么这么判断"，避免下次又从头评估一遍。

---

## 一、不引入的原因（三条，与好坏无关）

| 原因 | 说明 |
|---|---|
| 资源层重复 | 它有自研 `Resource` + `Download` + `FileSystem` 三件套；我们已用 YooAsset。它的 `Procedure / UI / Sound / Entity / DataTable` **全部依赖 `IResourceManager`**，引一个就得引一串 |
| 入口重复 | 它用全局 `GameFrameworkEntry` 单例挂所有模块；我们用 `ServiceLocator` + 分层 asmdef 划清边界。两套生命周期会打架 |
| 版本停滞 | master 最后几次提交在 2021 年。Unity 2021.3 能用，但 Unity 6 / 微信小游戏新 API 不再跟进 |

> 一句话：它的价值在**模块职责的划分方式**，不在代码本身。

---

## 二、逐模块取舍

| 它的模块 | 我们的现状 | 判断 | 处置 |
|---|---|---|---|
| ReferencePool | 只有 `GameObjectPool`（管 GameObject） | ✅ 缺 | **已写** `Core/ReferencePool.cs`：按类型分池 + `IReference.Clear()` + 可选严格校验 |
| TaskPool | 无；批量加载会一次性发起 N 个 AssetHandle | ✅ 缺 | **已写** `Core/TaskPool.cs`：协程限流，20 行调度，不引入它的 agent/优先级体系 |
| Sound | 只有 `BundleAssets/Audio/README.md` 规范 | ✅ 缺 | **已写** `Framework/Audio/AudioService.cs`：双 source 交叉淡入 + SFX 通道池 + 三层音量，**不依赖 AudioMixer** |
| DataTable | 只有 `BundleAssets/Config/` 目录规范 | ⏳ 缺，但要先定表结构契约 | 下一轮：轻量 `ConfigTable<T>`（YooAsset 异步加载 + 行基类），不做它的 Excel 解析器 |
| Localization | 只有 `BundleAssets/Text/` 目录规范 | ⏳ 缺 | 下一轮：key→string + 参数格式化 + 语言事件；不做"资源级本地化"（我们用 CDN 分语言包更简单） |
| Procedure | `Fsm` + `GameLauncher` 协程链已够 | ❌ 不引 | 借它的"流程上报进度"思想——`LaunchView` 已实现 |
| UI | `UIManager` 五层 + 面板栈 + 遮罩 | ❌ 不引 | 它多的是"UI 组深度 + 对象池回收"，我们靠层容器已解决 |
| Entity | 无 | ❌ 不引 | 实体系统是"框架替业务管 GameObject 生命周期"，我们让业务自己管更灵活，且与热更边界冲突 |
| Scene | `ResourceService.LoadScene` | ❌ 不引 | 多场景叠加用 Unity 原生 `LoadSceneMode.Additive` 即可 |
| Network | `NetworkService`（TCP + 心跳 + 重连 + seq 配对） | ❌ 不引 | 我们已超出它的能力（它没有断线重连与请求超时） |
| Setting | `PlayerPrefs` 直接调 | ❌ 不引 | 包一层价值太低；局外存档用版本化 JSON（见 `局外成长系统_20261027.md`） |
| WebRequest | `UnityWebRequest` 直接用 | ❌ 不引 | 无明显收益 |
| Debugger | 无运行时调试面板 | ⚠️ 有价值但非刚需 | 移动端真机调优时再做（FPS/内存/日志/切场景） |
| Config（全局只读配置） | `Resources/Config/*.json` | ❌ 不引 | 我们已有三份启动配置 |
| DataNode / FileSystem / Download / Encryption / Compression | 无 | ❌ 不引 | 与 YooAsset 职责重叠，或当前用不上 |

## 三、已落地的两个模块，改了什么

### ReferencePool（对比原版）

| 维度 | 原版 | 我们的 |
|---|---|---|
| 分池 | `Dictionary<Type, ReferenceCollection>` | 同思路 |
| 复位 | `IReference.Clear()` | 同 |
| 校验 | `EnableStrictCheck` 静态开关 | 保留，但把"重复释放检查"降级为**仅严格模式**（原版每次 Release 都 `Contains`，O(n)） |
| 统计 | 5 个计数器 | 同 |

### TaskPool（简化而非照搬）

原版是 `ITaskAgent` + 优先级队列 + 暂停/恢复状态机，为它的资源/实体/UI 全套服务。
我们只需要"限流跑协程"：`TaskPool.Run(tasks, concurrency, onDone, onProgress)`，
用 `GameLoop` 当宿主，异常隔离在单个任务里，一个任务炸了不拖垮整批。

### AudioService（重写，不复用它的结构）

| 维度 | 原版 Sound | 我们的 |
|---|---|---|
| 资源依赖 | 绑 `IResourceManager` + 声音组资产 | 绑 `ResourceService`，**零额外资产**（不依赖 AudioMixer） |
| 音量 | AudioMixer 组 + 快照 | 三层相乘（master × group × clip）+ PlayerPrefs |
| BGM 切换 | 单 source 硬切 | **双 source 交叉淡入**（硬切会爆音） |
| SFX | `PlayOneShot` | 固定通道池轮询（可控音量组、可丢弃最老） |
| 2D/3D | 支持 3D 跟随实体 | 只做 2D（我们的项目是 2D/斜 45° 视角，3D 音频无收益） |

## 四、下一轮候选（有明确前置条件）

| 模块 | 前置条件 | 为什么先不做 |
|---|---|---|
| `ConfigTable<T>` | 需要先定"表基类 + 主键 + 字段缺失策略"契约 | 契约定错，业务会写成两套解析 |
| `Localization` | 依赖 `Text/` 表结构 + 字体子集流程 | 与 TMP 字体子集刷新耦合，要一起设计 |
| `Debugger` | 无 | 真机调优阶段才有收益 |
