# 04 · 踩坑与判据表

> 用法：**先看现象，再看判据**。每条都标了"怎么确认"和"怎么改"，不要凭感觉改代码。
> 来源：框架实装过程中真实踩过的坑，按「现象 → 判据 → 处置」整理。每条都是先看到现象、再定位判据、最后给出可执行处置，不做推测式记录。

---

## 一、代码发布 / 程序集类

> 本框架**不做代码热更**：`Game.Business` 随包编译。所以这里不再是"热更炸了"，
> 而是"程序集边界 / 裁剪 / 引用"这一类问题。

| # | 现象 | 判据（怎么确认） | 处置 |
|---|---|---|---|
| 1 | 真机报"类型或命名空间不存在"，编辑器正常 | 用了 `Type.GetType("字符串")` 或 `Activator.CreateInstance(string)`，被 IL2CPP Strip 裁掉 | 改直接引用；确需反射就加 `[Preserve]` 或 `link.xml` |
| 2 | 改了代码但线上行为没变 | 是不是以为有代码热更 | 本框架代码随包发布：改代码必须重新出包，只有资源能热更 |
| 3 | 业务层编译报"引用了框架层内部类型" | 业务 asmdef 有没有反向引用 Editor / 私有实现 | 业务只依赖 `GameFramework.*` 公共 API，不要引 Editor 程序集 |
| 4 | `Assets/Game/Business` 改动导致全量重编 | 业务是否被并进 `Assembly-CSharp` | 确认 asmdef 存在且没被改名（`Game.Business`） |
| 5 | 启动页卡在"进入游戏…" | 业务入口抛异常 | 看 `[Launch] 业务入口异常` 的堆栈；`GameEntry.Start` 里加的 try/catch 会打出来 |
| 6 | 启动页永远停在进度条 | `Run(entry)` 传了 null | `Bootstrap` 里必须是 `Run(Game.Business.GameEntry.Start)` |

## 三、网络类

| # | 现象 | 判据 | 处置 |
|---|---|---|---|
| 15 | 偶发"收到的包解析乱码" | 半包/粘包没处理 | 必须走 `PacketSplitter.TryParse` 循环，不能一次读一个包 |

| 17 | 网络线程里碰 Unity API 报错 | `UnityException: can only be called from main thread` | 一律 `GameLoop.Post` 回主线程 |
| 18 | 断线重连后状态错乱 | 重连=新会话，服务端状态已重置 | 监听 `OnReconnected`，重新拉玩家数据，不要复用旧缓存 |
| 19 | 心跳正常但被判超时 | `heartbeatTimeout` ≤ 2 倍 `heartbeatInterval` | 超时值至少 3 倍心跳间隔 |
| 20 | 后台切回前台立刻掉线 | 移动端后台会掐 socket | 监听 `OnApplicationPause`，`false` 时主动重连 |
| 20.1 | 编辑器能连、WebGL/小游戏连不上 | ① `ws://` 被 https 页面当混合内容拦截 ② 域名白名单没配 | 改 `webSocketSecure: true`（wss）+ 微信后台加 socket 合法域名 |
| 20.2 | 小游戏 JS 日志说发了，C# 没收到 | `WebSocketBridge` 方法被 IL2CPP 裁掉 / GameObject 名不匹配 | 方法必须 `[Preserve]`；GO 名必须与 jslib 里一致（`WebSocketBridge`） |
| 20.3 | 一进联网模式就疯狂重连 | 连接建立前误触发"已断开" | `WebGLWebSocketBackend.Close` 用 `wasActive` 守住；别改回去 |
| 20.4 | 收到的包错乱/多出脏数据 | JS 侧 `send(HEAPU8 视图)` 没拷贝 | 必须 `HEAPU8.slice(ptr, ptr+len)` 再发 |
| 20.5 | 文本帧混进来把拆包器打乱 | 服务端混发 text 帧 | 协议只支持二进制；DotNet 后端会丢弃 text 并告警 |

## 六、"看不见"类问题排查位序（跨模块通用）

日志全绿、坐标/开关全对，但**屏幕上什么都没有**，按这个顺序查（前面命中率最高）：

```
1. 层级/排序         → Canvas sortingOrder / 同一个 Canvas 下的 sibling 顺序
2. 是否真的激活      → gameObject.activeInHierarchy（父节点关了也算没激活）
3. 尺寸与锚点        → 宽高是不是 0；锚点算出来的 rect 是不是在屏幕外
4. 颜色 alpha        → Image.color.a 是否为 0（代码默认值常常是 (1,1,1,0)）
5. 遮罩/裁切         → Mask / RectMask2D 范围
6. ZTest / 相机      → 3D 物体被 ZTest 挡；UI 相机 cullingMask 没包含该层
7. 池化污染          → 对象是从池里取的，上一任留下的状态没清（本框架 `GameObjectPool` 会 SetActive(true)，但业务自身的字段要自己清）
```

> 判据：`Renderer.isVisible` / `rectTransform.rect` 打日志，比截图可靠。

## 八、本框架已知边界（别踩到墙上才知道）

1. **只实现 TCP**。WebSocket/KCP 需新增 `INetChannel` 实现；小游戏平台必须换（WebGL 不支持裸 Socket）。
2. **`UIUtil.DefaultFont` 用系统字体**，仅够 Demo。正式项目接 TMP + 子集化字体（中文必须 `Noto Sans SC`）。
3. **没有账号/支付/统计 SDK**。这些是新增程序集（如 `GameFramework.Sdk`），不要塞进业务层——权限与回调都要求原生侧。
4. **不做代码热更**。改代码 = 发新包；只有资源能热更（`BundleAssets` → CDN）。
5. **PlayerPrefs 存档**只适合小数据；大量数据请用 YooAsset 的 RawFile 或自建文件层。
6. **`AutoBoot` 兜底**会自动创建 Bootstrap，正式项目建议主场景显式挂载并关掉兜底，避免战斗场景重复启动。
